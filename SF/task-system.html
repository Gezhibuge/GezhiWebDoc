任务系统

SF 的任务系统为玩家提供剧情方向，并帮助把过场动画与玩法串联起来。任务分为两大类：主线任务（Main） 与 支线任务（Side）。

你可以在示例地图关卡中找到这些任务的示例。

下面的教程会指导你设置任务，并在需要时管理它们。

补充说明 · 非官方 · Jay Versluis 的任务系统实战笔记

Jay 的文章把任务系统的常用操作串成了一条完整工作流，适合作为官方视频的文字补充：

  • 任务在哪里？ 任务队列属于物品栏管理器。你可以把任务加入队列，任务激活后再完成或判定失败；失败/完成后的“反应逻辑”需要你自己实现，SF 只提供接入点。
  • 创建任务。 在 NPC 对话的回复逻辑中，通过 对话回复时(On Dialogue Reply) 事件进入 按字符串切换(Switch on String)，为不同回复设置不同分支。创建任务时，先取得交互管理器引用，再调用 添加主任务到队列(Add Main Task to Queue)。数据录入最方便的做法是把任务结构提升为变量，再填默认值。若给任务设置计时器，玩家会看到倒计时，超时自动失败；计时器设为 0 表示不限时。
  • 完成任务。 调用 完成当前主任务(Complete Current Main Task)。队列中的下一个任务会自动上移并显示在右上角；如果没有后续任务，提示会消失。若玩家可能同时接多个任务，建议先取出当前任务，拆分出 任务标题(Task Header) 并做比较，确认完成的是正确的那一个。
  • 失败与修改。 失败任务同样有对应函数。任务进行到一半需要改目标时，用 编辑队列中的目标主任务(Edit Target Main Task in Queue)，它会更新当前任务的所有方面并同步到屏幕。注意：如果你改了 任务标题(Task Header)，后续用于判断“这是不是同一个任务”的检查也要同步修改，否则旧任务可能永远无法完成。
  • 查看队列。 可以读取队列来显示全部 upcoming 任务或已完成任务；也可以用 按标题在队列中查找任务(Find Task in Queue by Header) 查找特定任务。若只是想给玩家看回顾，日志与回忆录通常更合适。
  • 扩展任务结构。 需要给任务增加字段时，可以修改 TaskInfo_S 结构体（位于 StoryFramework > Core > Blueprints > Structures）。例如增加一个自定义枚举记录“已开始/已完成/已失败”，或按完成质量给分。

取物任务（Fetch Quest）的小例子： 玩家需要收集 3 根骨头。可在拾取物的 事件已销毁(Event Destroyed) 中，用 按名称在物品栏中查找物品(Find Item in Inventory by Name) 读取当前数量，并用这个数量更新任务标题，让玩家知道还剩几根；集齐后更新为“回去找发布任务的 NPC”，同时添加一个后果标签，解锁 NPC 的交付对话。Jay 还提醒了一个边界情况：如果任务开始时玩家已经集齐物品，要确保“已集齐”标签仍能正确发放，避免卡死。
